## Issue tracker

Read `99 System/Issue Tracker.md` before operating Wayfinder tickets.

## Wayfinder discipline

- Map = issue labelled `wayfinder:map`.
- Ticket = question, not an implementation slice.
- Ticket body starts with `Part of #<map>` when native sub-issues are not wired.
- `wayfinder:grilling` and `wayfinder:prototype` require the human.
- `wayfinder:research` is AFK research.
- Create only questions sharp enough to answer now; leave the rest in the map's `Not yet specified` fog.
- One resolved ticket per interactive session; research may run separately/in parallel.
- When the map clears, collapse decisions into a setup spec before implementing the final vault structure.

Human-facing project notes should be Czech unless there is a reason not to.
